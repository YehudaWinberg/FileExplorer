# FileExplorer - Epic Breakdown

## Overview

This document provides the complete epic and story breakdown for FileExplorer (חיפוש מתקדם), decomposing the requirements from the PRD, UX Design and Architecture into implementable stories.

## Requirements Inventory

### Functional Requirements

FR1: התאמת "מכיל" — חיפוש לפי חלק משם. `report.pdf` מחזיר גם `tempReport.pdf`; `re*ort` מחזיר `report` ו-`resort`.
FR2: תווים כלליים — `*` מתאים לכל רצף תווים (גם ריק), `?` לתו בודד. `א*א` מתאים ל-`אבא`; `?` לא מתאים לאפס תווים ולא לשניים.
FR3: אי-רגישות לרישיות — `Report` ו-`report` מחזירים אותן תוצאות.
FR4: סיומת — דפוס `*.xxx` או `שם*.xxx` מגביל לקבצים בעלי הסיומת (חלק השם "מכיל", הסיומת מדויקת). `report.pdf` הוא שם וסיומת יחד; `.pdf` לבדו הוא תבנית שם.
FR5: תיקיות וסיומת — כשיש סיומת בדפוס תיקיות אינן בתוצאות; בלעדיה גם תיקיות וגם קבצים יכולים להיות תוצאה.
FR6: סריקה לעומק — קובץ בעומק 5 מופיע; החיפוש מתחיל תמיד מהמיקום הנוכחי.
FR7: תוצאות בהדרגה, קרוב קודם — תוצאות נוספות במהלך הסריקה, פריטים קרובים לפני עמוקים, בלי מיון מחדש בזמן סריקה.
FR8: ביטול סריקה קודמת — הקלדה חדשה מבטלת סריקה פעילה; debounce של 300ms לפני תחילת סריקה.
FR9: חיווי התקדמות ועצירה — "סורק… נמצאו N"; כפתור עצירה (ריבוע) מפסיק סופית ושומר תוצאות; בקרי עצירה/השהיה מופיעים בתוך תיבת החיפוש רק אחרי תחילת חיפוש.
FR10: תיקיות ללא הרשאה — מדולגות בשקט, הסריקה ממשיכה.
FR11: דילוג על תיקיות כבדות — `node_modules` ו-`.git` לא נסרקות.
FR12: תקרת תוצאות — ב-500 (ערך סופי) הסריקה נעצרת, מוצגת הודעה שיש עוד, והפס מגיע ל-100%.
FR13: מיקום תיבת החיפוש — באותה שורה של כתובת התיקייה; כתובת גמישה, חיפוש ~280px; בפוקוס מתרחב ל-~50% והכתובת מתקצרת עם "…"; "בחירת תיקייה" הופך לאייקון קטן.
FR14: עמודות הטבלה — (1) אייקון, שם ותאריך שינוי מתחתיו, (2) נתיב, (3) גודל; נתיב ארוך מתקצר באמצע עם לפחות שתי תיקיות אחרונות; עד 4 חלקים במלואו.
FR15: אחוז קרבה — טבעת סביב האייקון + מספר (tooltip); שם זהה 100% לפני תיקון עומק; כיסוי חלקי לפי חלקו בשם (`א*א` מול `אבא` ≈ 67%); ללא תווים קבועים (`*.pdf`) בסיס 100%.
FR16: מיון ביוזמת המשתמש — אין מיון אוטומטי; כפתור "מיון לפי קרבה" גלוי תמיד, מושבת בסריקה פעילה, פעיל אחרי סיום/השהיה/הפסקה.
FR17: השפעת העומק — קנס 5 נקודות לכל רמת עומק (פריט ישיר = עומק 1), רצפה 0, מקסימום 95%; `?` תו קבוע; בשוויון הרדוד קודם.
FR18: חלונית בחירה — לחיצה כפולה פותחת חלונית עם "תצוגה מקדימה" ו"מעבר למיקום"; בתיקייה רק "מעבר למיקום".
FR19: מעבר למיקום — מציג את תיקיית הקובץ, מסמן את הקובץ, מעדכן את עץ התיקיות.
FR20: חזרה למסך תוצאות — אחרי מעבר למיקום, "אחורה" מחזיר למסך התוצאות עם אותן תוצאות; מצב החיפוש שורד ניווט.
FR21: יציאה ממסך תוצאות — לחיצה על תיקייה בעץ מנקה חיפוש ועוברת אליה; ניקוי התיבה חוזר למיקום הנוכחי.
FR22: אי-שבירה — כל מה שהחיפוש הישן מצא נמצא גם בחדש; קריאה בלבד (אין כתיבה/מחיקה/שינוי שם/רשת); שינוי "בחירת תיקייה" לאייקון לא פוגע ביכולת לבחור תיקייה (רגרסיה).
FR23: מצב ללא תוצאות — "לא נמצאו תוצאות" בסריקה שהסתיימה ריקה; הודעת הפסקה ("ייתכנו תוצאות נוספות") בעצירה ידנית.
FR24: השהיה והמשך — כפתור השהיה (שני פסים) ליד עצירה; השהיה שומרת תוצאות ומציגה "מושהה — נמצאו N"; המשך ממשיך מאותה נקודה בלי סריקה מחדש; אפשר לעצור סופית מהשהיה.
FR25: פס התקדמות — בתחתית התיבה, N/500; כחול בסריקה, כתום קפוא בהשהיה; בסיום קופץ ל-100% ונשאר; בעצירה ידנית נשאר במקומו.
FR26: תצוגה מקדימה בלחיצה אחת — בוחרת תוצאה ומציגה תצוגה מקדימה בחלונית הפרטים הקיימת; בתיקייה — פרטים בלי תצוגה מקדימה.

### NonFunctional Requirements

NFR1: ביצועים (SM-1) — קובץ בעומק 5 מופיע תוך ~5 שניות על עץ בדיקה של ~10,000 קבצים ב-5 רמות (יעד למדידה).
NFR2: ביצועים (SM-2) — התוצאה הראשונה, כשיש התאמה ברמה זהה או קרובה, מופיעה תוך שנייה על אותו עץ.
NFR3: נכונות (SM-3) — בדיקות יחידה מוכיחות ש-`report.pdf`, `*.pdf`, `re*ort` מחזירים את שהוגדר (FR1–FR5); רצות לפני PROD יחד עם בדיקת ביצועים.
NFR4: תאימות לאחור (SM-4/FR22) — חיפוש שם פשוט ממשיך לעבוד כמו היום.
NFR5: כיסוי (SM-C1) — מהירות הסריקה לא על חשבון כיסוי; רשימת התיקיות המדולגות מצומצמת ומתועדת (`node_modules`, `.git` בלבד).
NFR6: אבטחה/קריאה בלבד — אין כתיבה, מחיקה או שינוי שם בדיסק; אין Backend ואין קריאות רשת.
NFR7: תאימות דפדפן — Chrome/Edge בלבד (File System Access API); דסקטופ, עכבר ומקלדת, בלי מגע; Node 20+.
NFR8: נגישות מינימלית — `aria-label` ו-tooltip בעברית לכל בקר; מידע לא תלוי בצבע בלבד; חיווי סריקה כאזור live מנומס שאינו מכריז על כל תוצאה.
NFR9: יציבות UI — הרשימה לא קופצת ולא ממוינת מחדש בזמן קריאה; מספרים ב-`tabular-nums`.
NFR10: אימות — `npm run check` (typecheck + lint + tests) עובר אחרי כל שינוי; בלי ספריות חדשות.

### Additional Requirements

- אין starter template — פרויקט קיים (React 19, TS ~6.0, Vite 8, Vitest 4, oxlint); אין תלות חדשה.
- AD-1: `scanTree(adapter, root, compiled, signal)` כ-`AsyncGenerator<SearchResult>` ב-`src/lib/scanTree.ts`, בלי React ובלי Worker; מתודת Adapter קריאה-בלבד חדשה `listNames(folder)` (שם, סוג, מזהה) ב-`fileSystem.ts`; גודל ותאריך נטענים רק לתוצאות.
- AD-2: BFS לפי רמות; `yield` אחד לתוצאה; `SearchResult = { entry, parent: FolderRef, depth, score }`, עומק פריט ישיר = 1.
- AD-3: השהיה = אי-קריאה ל-`next()` בסטטוס `paused`; תוצאה בדרך בזמן השהיה נשמרת; עצירה/ביטול = `AbortController` + `return()` ותוצאה שחוזרת אחריהן נזרקת; יציאה מ-`Location` מסוג `search` בזמן `scanning` ממירה ל-`paused`; `resume` רק מ-`paused`.
- AD-4: `src/lib/utils/pattern.ts` — `compilePattern(raw)` → `{ nameRe, extension|null, fixedChars }` (בריחה לכל תו שאינו `*`/`?`), `scoreMatch(compiled, entry, depth)` → `number|null`, `Math.round`, שלם 0..95; `nameSearch.ts` הישן ופעולת reducer `search` נמחקים; אין סינון מיידי בזמן debounce.
- AD-5: `Location` מורחב ב-`{ type: 'search', root, pattern }`; `sameLocation` לפי `root.id` ודפוס מנורמל; חיפוש רק מ-`folder` (מושבת ב-`home`/`pc`/`quick`); אפקט יחיד ב-`SearchProvider` מפעיל סריקה; `start` על `search` מחליף רשומה (`replace`) וחותך forward; כשל בקריאת שורש = `done` עם 0 תוצאות.
- AD-6: `explorerReducer` כותב רק היסטוריה/בחירה/עץ; `searchReducer` כותב רק `SearchSession`; התחלת חיפוש רק דרך `search.start(pattern)`; כל ניווט דרך `goTo(location, { origin })`; `origin: 'user'` מנקה סשן + abort + debounce אטומית; `'result'` לא מנקה; back/forward לא מנקים.
- AD-7: `SearchResults` נפרד; `useSelectedEntry()` ו-`useVisibleEntries()` כמקור יחיד ל-`DetailsPane` ו-`StatusBar`; `navigate` מקבל `select?: id`; `App`, `Breadcrumbs`, `FileInfo`, `up`, `refresh` מטפלים ב-`search`.
- AD-8: תקרת 500 נאכפת רק בצרכן (סטטוס `capped`); `scanTree` תופס `FsError` מסוג `permission`/`not-found` לכל תיקייה; אין בקשת הרשאה באמצע סריקה; `SKIP_DIRS` קבוע יחיד ב-`lib/`.
- AD-9: `runId` עולה לכל `start`/`runSearch`; ה-reducer מתעלם מ-action עם `runId` שונה; ניקוי סשן מבצע abort.
- AD-10: `SearchSession = { runId, root, pattern, status, results, count, sortedByScore }` בעלים יחיד לדפוס; סדר = סדר הגעה; מיון קרבה = דגל `sortedByScore` (מיון יציב, שוויון לפי depth) פעיל רק כשהסטטוס אינו `scanning`.
- מכונת מצבים: idle → scanning ⇄ paused; scanning → done / capped / stopped; paused → stopped; done/stopped/capped → scanning ב-start.
- Blast radius: `FileList.tsx` (SearchBox מקומי, `searchQuery`, `filterByName`), `StatusBar.tsx`, `DetailsPane.tsx`, `App.tsx`, `Breadcrumbs.tsx`, `FileInfo.tsx`, `enter()`/`refresh` ב-`explorerReducer.ts`, ובדיקות `nameSearch.test.ts`, `FileSearch.test.tsx`, `explorerReducer.test.ts`.
- קונבנציות: פעולות reducer ב-camelCase באנגלית; בדיקות `*.test.ts` לצד הקוד; `id` של פריט = `parent.id/name`; שגיאות כ-`FsError`; כל שינוי מצב דרך reducer.
- בדיקת ביצועים ל-SM-1/SM-2 על עץ של ~10,000 קבצים ב-5 רמות; [ASSUMPTION] dispatch לכל תוצאה מאומת מול SM-1/SM-2.
- כללי פרויקט: ענף חדש לכל משימה; ללא `engines`/וירטואליזציה (נדחו); `.claude/rules/lib-operations.md` חל על `src/lib/**`.

### UX Design Requirements

UX-DR1: Design tokens — להרחיב את `src/styles/tokens.css` (בלי להמציא מחדש בסיס) בטוקנים: `scan-progress #0067c0`, `paused #c27a00`, `paused-bg #fff8ec`, `paused-text #7a4b00`, `field-underline #8d8d8d`, `row-hover #f5f5f5`, `result-selected #e6f0fa`, `ring-track #e0e0e0`, `ring-fill #0067c0`, `details-bg #fcfcfc`, `divider-vertical #d0d0d0`, `row-divider #f0f0f0`, `file-type-pdf #b3261e`; ממדים: `toolbar-height 44px`, `field-height 32px`, `result-row-height 52px`, `search-width 280px`, `search-width-focus 50%`, `details-width 300px`, `rounded.badge 8px`.
UX-DR2: top-bar (שורה עליונה B) בגובה 44px, gap 4px: ניווט (אחורה, קדימה, למעלה, רענון), אייקון בחירת תיקייה, address-field גמיש, search-box.
UX-DR3: address-field — breadcrumb בשדה לבן עם קו תחתון; בפוקוס חיפוש מתקצר ל-`… › שם-תיקייה`.
UX-DR4: search-box — 280px במנוחה, 50% בפוקוס עם אנימציה, קו תחתון 2px accent בפוקוס, זכוכית מגדלת בצד ההתחלה, בלוק בקרים בצד הסוף, רקע `paused-bg` וטקסט `paused-text` בהשהיה.
UX-DR5: search-control-button — 24px עם אייקון 12px; עצירה (ריבוע שחור), השהיה (שני פסים), המשך (משולש accent); רק בתוך התיבה ורק אחרי תחילת חיפוש; tooltip ו-`aria-label` `עצירה`/`השהיה`/`המשך`.
UX-DR6: scan-progress — פס 3px בתחתית התיבה, מתמלא מצד ההתחלה (ימין ב-RTL), רוחב = תוצאות/500, קופץ ל-100% ונשאר בסיום, כחול בסריקה וכתום בהשהיה; ללא ירוק.
UX-DR7: sort-button — "מיון לפי קרבה" עם אייקון, תמיד גלוי; מושבת בסריקה פעילה עם tooltip `המיון יהיה זמין בסיום הסריקה`; פעיל בהשהיה; מיון פעיל = קו תחתון accent. [ASSUMPTION: במצב ריק מושבת]
UX-DR8: result-row — גובה 52px; עמודות `minmax(0,1fr)` / 36% / 90px; שם + "שונה ב-<תאריך>" 12px; נתיב ב-`text-secondary`; גודל ב-tabular-nums; ריחוף `row-hover`; נבחרת `result-selected` + פס 3px accent; כניסת שורה חדשה באנימציה (שקיפות + הזזה 6px, 0.4s).
UX-DR9: proximity-ring — טבעת 38px, stroke 2.5px, אייקון 16px, קשת `ring-fill` מתחילה מלמעלה על מסלול `ring-track`, תג מספר 10px (גלולה, רקע לבן, מסגרת) בתחתית; מציג מספר וגם טבעת; לא מציג 100% לתוצאה.
UX-DR10: נתיב מקוצר — עד 4 חלקים במלואו, מעל: שורש + `…` + שתי תיקיות אחרונות; נתיב מלא ב-tooltip; `unicode-bidi: plaintext` ו-`bdi` לנתיבים מעורבים.
UX-DR11: preview-pane — החלונית הקיימת (300px, `details-bg`), לחיצה אחת מציגה תצוגה מקדימה; בלי בחירה: `בחרו תוצאה כדי לראות תצוגה מקדימה`; צל עדין רק על דף התצוגה המקדימה.
UX-DR12: מיקרו-קופי בעברית לפי טבלת Voice and Tone: `סורק… נמצאו N`, `מושהה — נמצאו N`, מצב ריק (`לא נמצאו תוצאות` + תת-כותרת + רמז `נסו שם קצר יותר, למשל כהן*`), `N תוצאות`, `הסריקה הופסקה — ייתכנו תוצאות נוספות`, `הוצגו 500 תוצאות — יש עוד. צמצמו את החיפוש`; בלי סימני קריאה/אימוג'י.
UX-DR13: מצבי UI — מנוחה (ללא פס וללא בקרים), סריקה, מושהה, הסתיימה (בקרים נעלמים, פס מלא), ריק, הופסקה, תקרת 500, נבחרה תוצאה, פוקוס בתיבה; תיקיות ללא הרשאה — שקט מוחלט.
UX-DR14: חלונית בחירה (FR-18) — לא עוצבה; לתכנן במינימליזם בסגנון Fluent עם שתי פעולות; לתיקייה רק "מעבר למיקום". [פער פתוח]
UX-DR15: נגישות מינימלית — `aria-label` + tooltip בעברית לכל הבקרים (`בחירת תיקייה`, `אחורה`, `קדימה`, `למעלה`, `רענון` ועוד); אזור live מנומס לחיווי הסריקה; מצב מושהה גם בטקסט.
UX-DR16: אילוצי תחום — מצב בהיר בלבד, בלי מצב כהה; בלי ספריית רכיבים; קיצורי מקלדת (Ctrl+F, Esc, חצים) מחוץ להיקף כרגע.
UX-DR17: איחוד טוקנים — להכריע ביישום בין `result-selected`/`bg-selected` ו-`field-underline`/`border-strong` (הקיים נשמר, החדש נוסף בנפרד).

**Then** הסריקה ממשיכה מהנקודה שבה הושהתה, בלי סריקה מחדש ובלי כפילויות או אובדן תוצאות, והסטטוס חוזר ל-`scanning`

**Given** מצב מושהה
**When** לוחצים עצירה
**Then** הסטטוס `stopped` והתוצאות נשמרות; אי אפשר `resume` מ-`stopped`, `done` או `capped`, רק `start` חדש (AD-3)

**When** המשתמש מנווט מ-`search` למיקום אחר באמצעות back/forward

**Given** מכונת המצבים
**When** קיימת תוצאה שהגיעה אחרי עצירה או ביטול
**Then** היא נזרקת (AD-3, AD-9)

**And** מצב מושהה מוצג גם בטקסט ולא רק בצבע (UX-DR15); בדיקות reducer ו-`useSearch` לכל המעברים; `npm run check` ירוק.

### Story 2.2: פס התקדמות

As a משתמש,

**Given** מצב מושהה
**When** הפס מוצג
**Then** הוא קפוא בצבע `paused` (כתום) ברוחבו הנוכחי

**Given** סריקה שהסתיימה (`done`) גם עם פחות מ-500 תוצאות
**When** הסטטוס משתנה
**Then** הפס קופץ מיד ל-100% ונשאר מלא וכחול (לא נעלם ולא ירוק)

**Given** עצירה ידנית (`stopped`)
**When** הפס מוצג
**Then** הוא נשאר ברוחב שבו נעצר

**Given** מצב מנוחה (ללא חיפוש)
**When** התיבה מוצגת
**Then** אין פס ואין בקרים

**Given** `capped`

**Then** הוא ב-100%

**And** הפס אינו מכריז לקורא מסך (עיטור בלבד, החיווי הטקסטואלי הוא האזור ה-live); בדיקות רכיב לכל המצבים; `npm run check` ירוק.

### Story 2.3: תקרת 500 והודעת הפסקה

**Given** `scanTree`

**When** מתחילים חיפוש חדש

**And** ההודעות בעברית קצרה ובלי סימני קריאה או אימוג'י (UX-DR12, UX-DR13); בדיקות reducer ורכיב; `npm run check` ירוק.

## Epic 3: הבנת הקרבה ומיון

כל תוצאה מקבלת טבעת קרבה ומספר, והמשתמש ממיין לפי קרבה בסיום, בהשהיה או בהפסקה.

### Story 3.1: חישוב אחוז קרבה

As a משתמש,
I want שכל תוצאה תקבל ציון שמשקף כמה היא קרובה למה שחיפשתי,
So that אוכל לדעת איזו תוצאה סבירה יותר.

**Acceptance Criteria:**

**Given** `scoreMatch(compiled, entry, depth)` ב-`src/lib/utils/pattern.ts`
**When** אין התאמה
**Then** מוחזר `null`

**Given** שם זהה לדפוס (למשל `אבא` מול `אבא`)
**When** מחשבים בסיס שם
**Then** הבסיס 100% לפני תיקון עומק (FR15)

**Given** `א*א` מול `אבא`
**When** מחשבים בסיס שם
**Then** הבסיס הוא 2/3, כלומר כ-67% (FR15)

**Given** דפוס ללא תווים קבועים (`*.pdf`)
**When** מחשבים בסיס שם
**Then** הבסיס 100%, והסיומת אינה נספרת כשאין סיומת בדפוס (FR15)

**Given** `?` בדפוס
**When** מחשבים `fixedChars`
**Then** `?` נחשב תו קבוע (FR17)

**Given** עומק של פריט
**When** מחשבים ציון סופי
**Then** מופחתות 5 נקודות לכל רמת עומק, רצפה ב-0, גם להתאמה מלאה: עומק 1 = 95, עומק 3 = 85 (FR17)

**Given** ציון עשרוני
**When** הוא מוחזר
**Then** מעוגל ב-`Math.round` לשלם בטווח 0..95; לעולם לא 100 לתוצאה

**Given** שתי תוצאות עם אותה התאמת שם
**When** משווים
**Then** זו שקרובה יותר למיקום הנוכחי מקבלת ציון גבוה יותר

**Given** `scanTree`
**When** הוא מפיק תוצאה
**Then** `score` מחושב דרך `scoreMatch` ומחליף את הערך הזמני 0 מ-Epic 1; סדר ה-BFS אינו משתנה

**And** נוסחת הקרבה חיה רק ב-`pattern.ts` (AD-4); בדיקות יחידה לדוגמאות מה-PRD (`אבא`, `א*א`, `*.pdf`, `?`); `npm run check` ירוק.

### Story 3.2: טבעת קרבה בשורת תוצאה

As a משתמש,
I want לראות את אחוז הקרבה כטבעת סביב האייקון וכמספר,
So that אבין במבט אחד מה הכי קרוב למה שחיפשתי, בלי להסתמך על צבע בלבד.

**Acceptance Criteria:**

**Given** שורת תוצאה
**When** היא מוצגת
**Then** סביב האייקון (16px) מוצגת טבעת 38px, stroke 2.5px, קשת `ring-fill` שמתחילה מלמעלה ומתמלאת ביחס לאחוז על מסלול `ring-track` (UX-DR9)

**Given** תוצאה עם ציון
**When** השורה מוצגת
**Then** תג מספר (10px, גלולה עם רקע לבן ומסגרת) תלוי בתחתית הטבעת, והמספר מופיע גם ב-tooltip (FR15)

**Given** ציון 0
**When** הטבעת מוצגת
**Then** מוצג מסלול ריק ותג `0`, בלי שגיאה

**Given** תוצאה בעומק 1 עם התאמה מלאה
**When** הטבעת מוצגת
**Then** מוצג 95 ולא 100 (FR17)

**Given** קורא מסך
**When** השורה מוצגת
**Then** אחוז הקרבה זמין בטקסט (aria), כך שהמידע אינו תלוי בצבע או בטבעת (UX-DR15)

**And** הטבעת אינה גורמת להזזת השורות בזמן סריקה (NFR9); בדיקות רכיב לערכים 0, 67, 85, 95; `npm run check` ירוק.

### Story 3.3: מיון לפי קרבה

As a משתמש,

**Acceptance Criteria:**

**Given** מסך תוצאות

**Given** סטטוס `scanning`
**When** הכפתור מוצג
**Then** הוא מושבת (`text-disabled`) עם tooltip `המיון יהיה זמין בסיום הסריקה`

**Given** סטטוס `done`, `paused`, `stopped` או `capped`

**Given** סשן בלי תוצאות (מצב ריק)

**Then** `sortedByScore` הופך ל-`true` והתוצאות מסתדרות לפי ציון יורד במיון יציב, ובשוויון הפריט הרדוד יותר קודם (AD-10)

**Given** מיון פעיל
**When** הכפתור מוצג
**Then** יש לו קו תחתון accent

**Given** הרשימה בזמן סריקה
**When** תוצאות נוספות מגיעות
**Then** הרשימה אינה ממוינת אוטומטית והסדר הוא סדר ההגעה (FR16)

**Given** מיון פעיל והמשתמש לוחץ המשך (resume)
**When** הסריקה חוזרת ל-`scanning`
**Then** הדגל `sortedByScore` מתאפס והרשימה חוזרת לסדר ההגעה, והכפתור מושבת שוב

**Given** `explorerReducer.sort`
**When** מופעל

**And** בדיקות reducer ורכיב; `npm run check` ירוק.

## Epic 4: מעבר מתוצאה למיקום וחזרה

לחיצה אחת מציגה תצוגה מקדימה, לחיצה כפולה פותחת חלונית בחירה ומשם עוברים למיקום הקובץ, ו"אחורה" מחזיר למסך התוצאות.

### Story 4.1: תצוגה מקדימה בלחיצה אחת

As a משתמש,
I want ללחוץ פעם אחת על תוצאה ולראות תצוגה מקדימה שלה,

**Acceptance Criteria:**

**Given** מסך תוצאות
**When** לוחצים פעם אחת על תוצאת קובץ
**Then** השורה נבחרת (`result-selected` + פס 3px accent) ובחלונית הפרטים הקיימת (300px, `details-bg`) מוצגת תצוגה מקדימה, ללא פתיחת חלונית בחירה (FR26, UX-DR8, UX-DR11)

**Given** תוצאה שהיא תיקייה
**When** לוחצים עליה פעם אחת
**Then** מוצגים פרטי התיקייה בלי תצוגה מקדימה (FR26)

**Given** אין תוצאה נבחרת
**When** חלונית הפרטים מוצגת

**Given** `useSelectedEntry()`
**When** `DetailsPane` מציג פריט
**Then** מקור הפריט הוא ההוק בלבד, ופריט נבחר נמצא לפי מזהה `parent.id/name` הייחודי גלובלית (AD-7)

**Given** סריקה פעילה
**When** תוצאות חדשות מצטרפות
**Then** הבחירה והתצוגה המקדימה נשארות יציבות

**Given** הקובץ הנבחר
**When** התצוגה המקדימה נטענת
**Then** היא זהה לזו של קבצים רגילים, קריאה בלבד וללא כתיבה לדיסק (FR22, NFR6)

**And** בדיקות רכיב; `npm run check` ירוק.

### Story 4.2: חלונית בחירה ומעבר למיקום

As a משתמש,

**Acceptance Criteria:**

**Given** מסך תוצאות

**Then** נפתחת חלונית בחירה עם שתי פעולות: "תצוגה מקדימה" ו"מעבר למיקום" (FR18)

**Given** תוצאה שהיא תיקייה
**When** לוחצים עליה פעמיים
**Then** החלונית מציעה רק "מעבר למיקום" (FR18)

**Given** חלונית הבחירה
**When** היא מוצגת
**Then** עיצובה מינימלי בסגנון Fluent על טוקנים קיימים (רקע `bg-layer`, מסגרת `border`, רדיוס `lg`, בלי צללים לשם היררכיה), נסגרת ב-Esc ובלחיצה מחוץ לה, עם `aria-label` בעברית (UX-DR14, UX-DR15)

**Then** מוצגת תיקיית הקובץ, הקובץ מסומן ברשימה, ועץ התיקיות מתעדכן למיקום החדש (FR19)

**And** הפעולות לקריאה בלבד (NFR6); בדיקות רכיב ו-reducer; `npm run check` ירוק.

### Story 4.3: חזרה למסך התוצאות

**And** בדיקות אינטגרציה לתרחיש UJ-1 המלא: חיפוש, בחירה, לחיצה כפולה, מעבר למיקום, אחורה; `npm run check` ירוק.
