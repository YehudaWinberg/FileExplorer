# Product Brief: Hook שומר קבצים רגישים (Harness Engineering, תרגיל Level 6)

## Executive Summary

מוסיפים ל-Claude Code ב-FileExplorer שכבת הגנה שנייה. hook מסוג `PreToolUse` שרץ לפני שהסוכן קורא או כותב קובץ, ו**חוסם** גישה לשני סוגי קבצים: קבצי `.env` (סודות) וקובץ `settings.json` של Claude (תצורת ה-harness, כולל ה-hooks עצמם).

ה-hook מחזיר JSON עם `permissionDecision: "deny"` וסיבה בעברית, כך שהסוכן מבין למה נחסם ולא מנסה לעקוף. כל קובץ אחר עובר ללא הפרעה. זהו תרגיל לימודי בקורס Harness Engineering, ולכן החשיבות היא גם בלמידה: הפרדת לוגיקה (`guard-files`) מאדפטר (קובץ ה-hook), עם בדיקות אוטומטיות.

## The Problem

- בלי חסימה, הסוכן יכול לקרוא `.env` ולהכניס סודות להקשר השיחה.
- הסוכן יכול לערוך `settings.json` ולהסיר או להחליש את ה-hooks שמגנים עליו. אז ההגנה הקיימת (`bash-guard`) ניתנת לעקיפה.
- ה-hook הקיים מכסה רק פקודות Bash ו-PowerShell (מחיקה רקורסיבית, publish, git שכותב להיסטוריה). אין כיסוי לכלי הקריאה והכתיבה.

## The Solution

hook חדש שרץ על כלי קבצים. הוא מקבל JSON ב-stdin, בודק את נתיב הקובץ, ואם הנתיב מוגן מחזיר `deny` עם הסבר. הלוגיקה והאדפטר מופרדים:

- **`guard-files.mjs`**: פונקציה טהורה `checkFilePath(path)` שמחזירה `{blocked, reason}`. אין בה I/O, וקל לבדוק אותה.
- **אדפטר ה-hook** (שם סופי להחלטה, ראו שאלות פתוחות): קורא stdin, מפיק את הנתיב מ-`tool_input`, קורא ל-`guard-files` ומדפיס JSON.
- **בדיקות** (`node:test`, כמו ב-`bash-guard.test.mjs`): נתיב מוגן מקבל deny, וכל השאר מותר.

פורמט הפלט:

```json
{ "hookSpecificOutput": { "hookEventName": "PreToolUse", "permissionDecision": "deny", "permissionDecisionReason": "..." } }
```

## What Makes This Different

ה-hook הקיים חוסם עם `exit 2` והודעה ב-stderr, וה-hook החדש משתמש בפלט JSON מובנה. זו ההבחנה הלימודית של התרגיל, ואין כאן יתרון תחרותי. ההגנה היא ברמת ה-harness (דטרמיניסטית), ולא בהוראה לסוכן ב-CLAUDE.md שהוא יכול להתעלם ממנה.

## Who This Serves

**yehuda**, מפתח הפרויקט, הלומד Harness Engineering. הוא רוצה שהסוכן יעבוד בחופשיות בפרויקט, אבל לא ייגע בסודות ובתצורת ה-harness. משני: סוכן Claude, שמקבל סיבה ברורה ולא רק כישלון.

## Success Criteria

1. קריאה או כתיבה (`Read`, `Edit`, `Write`) של כל קובץ env או `settings.json` מחזירה `deny` עם סיבה.
2. כל קובץ אחר, כמו `src/App.tsx` או `package.json`, מותר ללא שינוי בהתנהגות.
3. נתיבי Windows (`\`), אותיות גדולות וקטנות, ונתיבים יחסיים ומוחלטים מטופלים נכון.
4. קלט פגום או חסר מחזיר deny עם הסבר.
5. `npm run check` עובר במלואו, והבדיקות החדשות כלולות בו.
6. ההתנהגות של `bash-guard` הקיים נשמרת, והבדיקות שלו עוברות אחרי המעבר לתיקייה החדשה.

## Scope

**בפנים**
- `guard-files` + אדפטר + בדיקות.
- רישום ב-`.claude/settings.json`: matcher לכלי קבצים.
- ארגון מחדש של `.claude/hooks/` לתיקיות משנה. ה-hook הקיים עובר ל-`critical/`, והחדש לתיקייה משלו. עדכון הנתיב ב-settings ובייבוא הבדיקות.
- חסימת קריאה גם דרך PowerShell, כמו `Get-Content .env`: בדיקה היוריסטית של טוקנים בפקודה, כי המשתמש עובד ב-Windows.

**בחוץ**
- חסימה של `Glob`: הוא מחזיר רק שמות קבצים, לא תוכן.
- זיהוי עקיפות מתוחכמות (קידוד, משתני סביבה, `bash -c`). ההגנה היא ניתוח טקסט, וכך תתועד.
- חסימה של `settings.local.json`: לא נדרש.

## החלטות שהתקבלו

| נושא | החלטה |
|---|---|
| Matcher | `Read\|Edit\|Write`. המשתמש כתב `Edit\|Write`, אבל חסימת קריאה דורשת גם `Read`. יש להוסיף `Grep` ו-`PowerShell` (ראו שאלות פתוחות). |
| hook אחד או כמה | **כמה hooks נפרדים.** כל פקודת hook מפעילה תהליך Node נפרד (עשרות אלפיות שנייה), ו-hooks שמתאימים לאותו אירוע רצים **במקביל**. לכן הפיצול לא מוסיף השהיה משמעותית. המטרה היא הפרדת אחריות, כללים שמתפתחים בנפרד ובדיקות ממוקדות. איחוד היה מערבב חסימת פקודות עם חסימת קבצים. |
| Grep | רלוונטי חלקית. `Grep` מחזיר **תוכן** שורות, ולכן חיפוש בתיקייה יחשוף ערכים מ-`.env`. ניתן לחסום כשה-`path` מצביע ישירות על קובץ מוגן או כשה-`glob` מתאים. חיפוש כללי בתיקייה אי אפשר לחסום ברמת ה-hook בלי למנוע את כל החיפושים. הסיכון נשאר ויתועד. |
| Glob | לא רלוונטי: רק שמות קבצים. |
| קבצים מוגנים | שם הקובץ מסתיים ב-`.env` או מתחיל ב-`.env.`, וגם `settings.json`. ה-`settings.json` מוגן רק מתחת לתיקיית `.claude`, כפי שהמשתמש הגדיר בפרומט המקורי. כך לא ייחסמו `package.json`-דומים או `settings.json` של כלים אחרים. |
| כשל | קלט פגום, חסר נתיב או שגיאה פנימית מחזירים deny עם הסיבה (fail closed). זה שונה מ-`bash-guard`, שנכשל פתוח. |
| סיבה | הודעה בעברית וברורה, עם שם הקובץ ומה אפשר לעשות במקום. |

## החלטות סופיות (אושרו על ידי המשתמש)

1. שם האדפטר: `file-guard.mjs` מעל `guard-files.mjs`, בתיקייה `.claude/hooks/files/`. ה-hook הקיים עובר ל-`.claude/hooks/critical/`.
2. `.env.example` ו-`.env.sample` נחסמים, לפי "כל קובץ env".
3. `~/.claude/settings.json` ברמת המשתמש נחסם, כי הוא מתחת לתיקיית `.claude`.
4. PowerShell בתחום: בדיקה היוריסטית של טוקנים בפקודה, ללא הבטחה לכיסוי מלא.
5. Matcher סופי: `Read|Edit|Write|Grep|PowerShell`.

## סיכוני ארגון מחדש

העברת `bash-guard` לתיקייה אחרת משנה את הנתיב ב-`settings.json`, את ה-imports ב-`bash-guard.test.mjs` ואת ההפניות בפרומטים. יש לעשות זאת בצעד נפרד, להריץ `npm run check` לפני ואחרי, ולא לשנות לוגיקה. בהתאם ל-AGENTS.md, אין commit בלי אישור מפורש.

## Vision

אוסף hooks מסודר בתיקיות לפי מטרה (`critical/`, `files/` ועוד), שבו כל כלל מתועד ונבדק ואפשר להוסיף כללים חדשים בלי לגעת בקיימים.
