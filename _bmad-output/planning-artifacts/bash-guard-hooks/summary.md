# סיכום אפיון: hook שומר לפקודות Bash / PowerShell

נכתב על ידי מרי (אנליסטית), 2026-11-13. זה אפיון בלבד: **לא בוצע שום מימוש.**
הצעד הבא: העברה לאמיליה (`bmad-agent-dev`) למימוש.

## מטרה

למנוע מה-agent לבצע פעולות שהמשתמש שומר לעצמו, כדי שהוא ישלוט במה שנמחק, מה שמפורסם ומה שנכנס להיסטוריית git.

## מנגנון (סוכם)

- hook מסוג `PreToolUse` שרץ לפני כלי Bash וגם לפני כלי PowerShell (הפרויקט על Windows, ו-hook על Bash בלבד היה נעקף).
- חסימה מוחלטת: אין מנגנון עקיפה. ההודעה ל-agent אומרת שהפעולה שמורה למשתמש.
- ההודעות ל-agent בעברית.

## הכללים

### 1. מחיקה רקורסיבית: חסום

| נחסם | מותר |
|---|---|
| `rm -r/-rf/-fr`, `rm --recursive` | מחיקת קובץ בודד |
| `rmdir /s`, `del /s` | |
| `Remove-Item -Recurse` (כולל קיצורי פרמטר), `ri -r` | |
| `find ... -delete` | |

הודעה ל-agent: מחיקה רקורסיבית אסורה. אפשר להציג למשתמש רשימת נתיבים והמשתמש יבצע.

### 2. publish: חסום

- `npm/pnpm/yarn publish`, `unpublish`, `deprecate`.
- המשתמש מבצע publish בעצמו.
- `npm run build` ו-`npm install` מותרים.

### 3. git

**חסום (כתיבה):** `commit`, `push`, `force push`.

**חסום (אובדן מידע):**
- `reset --hard`
- `clean` (מותר רק עם `--dry-run`)
- `restore` (מותר רק עם `--staged`)
- `checkout` ו-`switch` עם force
- `branch -d/-D/-M`
- `stash drop/clear`
- `tag -d`
- `git rm`
- `reflog`, `gc`, `prune`, `filter-branch`

**מותר (הוסכם במפורש):** בדיקת מצב (`git status`), `git diff`, `git log`, יצירת ענף חדש (`git branch <name>`, `git checkout -b`, `git switch -c`).

## החלטות שהוכרעו בהמשך (2026-11-13)

1. `merge`, `rebase`, `cherry-pick`, `revert`, `am`: **חסומים.**
2. `docker push` ו-`gh release create`: **חסומים** (נחשבים publish).
3. הפרומט של המשימה **נשמר ב-`promt/`** על ידי אמיליה, כחלק מהמשימה.

אין החלטות פתוחות.

## מגבלות ידועות

- ההגנה מבוססת על ניתוח מחרוזת הפקודה. פקודות עטופות (`bash -c`), משתנים, סקריפטים עקיפים ו-git aliases עלולים לעבור.
- false positives אפשריים (למשל `echo "git push"`).
- ה-hook לא משפיע על פקודות שהמשתמש מריץ בעצמו.
- ה-hook נטען בהפעלת session, ולכן נדרש session חדש או `/hooks`.
- תופעת לוואי שנצפתה בניסיון הראשון: ה-hook חוסם גם את ביטול השינויים של עצמו (`git restore`). בעת הסרה יש לערוך את `settings.json` ישירות.

## הנחיות למימוש (לאמיליה)

- ענף חדש לפי כלל הפרויקט. אין commit, push או PR.
- ללא ספריות חדשות. סקריפט Node ב-`.claude/hooks/`, חיבור ב-`.claude/settings.json`.
- לפני שמתחילים: לקרוא את [CONTRACT.html](../../../CONTRACT.html) בשורש הפרויקט. זו טבלת הכללים (נושא, פקודה, החלטה, אכיפה), והיא גוברת על הסיכום הזה אם יש סתירה. בסיום המימוש יש לעדכן בה את עמודת האכיפה.
- בדיקות Vitest לחסום ולמותר.
- בדיקות הצלחה/כישלון מקצה לקצה: הרצת הסקריפט כתהליך עם JSON ב-stdin. `git push` / `npm publish` נכשלים (exit 2 + הודעה), `git diff` מצליח (exit 0).
- בנוסף, בדיקות יחידה לכל כלל ולכל וריאציה.
- `npm run check` חייב לעבור לפני דיווח הצלחה.
- ניסיון מימוש קודם נמחק במלואו (קבצים, `settings.json`, ענף), כך שמתחילים מאפס.
