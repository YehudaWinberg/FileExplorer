# תרגיל 2 — פיתוח פיצ'ר באמצעות Prompt בן שש שכבות

## 1. Role — תפקיד

אתה מפתח Web בכיר, מומחה ב-React וב-TypeScript, בעל ניסיון רב בהרחבת מערכות קיימות.

אתה מתמחה בהשתלבות בארכיטקטורה קיימת, בשמירה על תאימות לאחור ובפיתוח קוד איכותי, מודולרי וניתן לבדיקה.

## 2. Context + Reason — רקע וסיבה

**רקע:**

המערכת היא FileExplorer המבוססת על React ו-TypeScript ומשתמשת ב-File System Access API של הדפדפן.

המשתמש בוחר תיקייה ורואה את הקבצים והתיקיות שבתוכה.

כיום קיימת חלונית בצד שמאל המציגה מידע בסיסי על הקובץ הנבחר: שם, סוג, גודל ותאריך שינוי אחרון.

**סיבה:**

המידע המוצג כיום אינו מספיק למשתמש שרוצה להבין את מאפייני הקובץ ולזהות אותו לפני פתיחתו.

מטרת הפיצ'ר היא להרחיב את המידע המוצג בחלונית הקיימת, ולאפשר למשתמש לזהות קבצים בקלות, ובמיוחד לצפות בתמונות ובנתונים שלהן בלי לפתוח אותן בנפרד.

## 3. Task — משימה

נדרש להרחיב את חלונית פרטי הקובץ הקיימת באמצעות רכיב React חדש שיוצג בתוכה.

### 3.1 התנהגות בחירת קובץ

- לחיצה בודדת על קובץ תציג את פרטיו בחלונית.
- בחירת קובץ אחר תחליף את המידע של הקובץ הקודם.
- בחירת תיקייה או מעבר לתיקייה אחרת ינקו את פרטי הקובץ הקודם.
- אין להציג מידע השייך לקובץ שנבחר קודם, גם אם פעולת טעינה אסינכרונית שלו הסתיימה לאחר בחירת קובץ חדש.

### 3.2 הצגת מידע כללי על הקובץ

יש להציג את הפרטים הבאים, ככל שהם זמינים:

- שם הקובץ.
- סוג הקובץ.
- תוכנה נפוצה שבאמצעותה ניתן לפתוח את הקובץ.
- מיקום הקובץ ביחס לתיקיית השורש שבחר המשתמש.
- גודל הקובץ ב-MB.
- תאריך שינוי אחרון.

**תוכנה לפתיחת הקובץ:**

יש להגדיר מיפוי מקומי בין סיומות קבצים נפוצות לבין תוכנות שבדרך כלל משמשות לפתיחתן.

אין צורך לזהות את תוכנת ברירת המחדל שמוגדרת במחשב המשתמש.

עבור סיומות לא מוכרות, אין להציג את שדה התוכנה. אין לבצע חיפוש באינטרנט.

**מידע חסר:**

כאשר ערך מסוים אינו זמין, יש להסתיר את השדה הרלוונטי. אין להציג מידע משוער כאילו הוא מידע אמיתי.

### 3.3 מידע נוסף עבור תמונות

כאשר המשתמש בוחר קובץ תמונה נתמך, נדרש להציג:

- רוחב התמונה בפיקסלים.
- גובה התמונה בפיקסלים.
- כל נתוני ה-EXIF הזמינים בקובץ.
- תצוגה מקדימה של התמונה.

נתוני EXIF ייקראו מתוך תוכן הקובץ באמצעות עיבוד בצד הדפדפן.

אם אין נתוני EXIF, יש להציג הודעה מתאימה באזור ה-EXIF.

### 3.4 תצוגה מקדימה

התצוגה המקדימה של התמונה תופיע באזור נפרד בחלק התחתון של החלונית השמאלית הקיימת.

אם לא ניתן להציג את התמונה, יש להציג הודעה באזור התצוגה המקדימה.

כישלון בהצגת התמונה לא יפגע בהצגת שאר פרטי הקובץ.

כאשר נבחר קובץ שאינו תמונה, יש להסיר את התצוגה המקדימה ואת המידע הייחודי לתמונה הקודמת.

### 3.5 טעינה הדרגתית

- יש להציג את פרטי הקובץ הבסיסיים מיד כשהם זמינים.
- נתוני EXIF והתצוגה המקדימה ייטענו בנפרד.
- בזמן טעינת מידע נוסף יש להציג חיווי טעינה מתאים.
- כישלון בטעינת מידע מסוים לא יכשיל את טעינת שאר המידע.
- בכל רגע יוצג מידע השייך לקובץ האחרון שנבחר בלבד.

## 4. Scope & Done — גבולות המשימה וקריטריוני סיום

### 4.1 גבולות המשימה

- יש לבצע רק את השינויים הנדרשים למימוש הפיצ'ר.
- מותר לשנות קבצים קיימים רק כאשר השינוי נחוץ למימוש או לשילוב הפיצ'ר.
- אין לבצע Refactoring שאינו קשור למשימה.
- אין לתקן תקלות אחרות שהתגלו במהלך העבודה.
- יש לשמור על ההתנהגות הקיימת של המערכת.
- יש להשתמש ב-File System Access API וביכולות עיבוד בצד הדפדפן.
- אין להוסיף Backend או שירותי אינטרנט חיצוניים.
- יש להעדיף שימוש בספריות שכבר קיימות בפרויקט.
- מותר להוסיף ספרייה חיצונית לחילוץ EXIF אם היא נחוצה. במקרה כזה יש לדווח על כך בסיום.
- יש לפעול בהתאם לכללי הפרויקט ולמבנה הקוד הקיים.

### 4.2 קריטריוני סיום — Definition of Done

המשימה תיחשב כמושלמת רק לאחר שכל התנאים הבאים מתקיימים:

1. רכיב React חדש מציג את המידע המורחב בתוך החלונית השמאלית הקיימת.
2. פרטי הקובץ הכלליים מוצגים בצורה תקינה.
3. בחירת קובץ אחר מחליפה את כל המידע הקודם.
4. בחירת תיקייה מנקה את פרטי הקובץ.
5. מידות תמונה ונתוני EXIF מוצגים כאשר הם זמינים.
6. כאשר אין EXIF מוצגת הודעה מתאימה.
7. תצוגה מקדימה מוצגת עבור תמונות נתמכות.
8. כישלון בטעינת תמונה או EXIF אינו פוגע בהצגת שאר פרטי הקובץ.
9. טעינה אסינכרונית מאוחרת אינה גורמת להצגת מידע מקובץ קודם.

### 4.3 בדיקות אוטומטיות

יש להוסיף בדיקות אוטומטיות המכסות לפחות את התרחישים הבאים:

1. בחירת קובץ מציגה את פרטיו.
2. בחירת קובץ אחר מחליפה את המידע הקודם.
3. בחירת תיקייה מנקה את פרטי הקובץ.
4. תמונה עם EXIF מציגה את נתוני ה-EXIF.
5. תמונה ללא EXIF מציגה הודעה מתאימה.
6. בחירת תמונה מציגה תצוגה מקדימה.
7. בחירת קובץ שאינו תמונה מסירה את התצוגה המקדימה הקודמת.
8. בחירה מהירה של שני קבצים אינה גורמת להצגת מידע ישן.

יש להריץ את כל הבדיקות הקיימות בפרויקט ולוודא שהן עוברות בהצלחה.

יש לזהות את פקודות הבדיקה וה-Check מתוך הגדרות הפרויקט ולהריץ אותן.

יש לוודא שהפיצ'ר עובד גם באפליקציה הרצה, ולא להסתפק בבדיקות יחידה בלבד.

### 4.4 שמירת ה-Prompt ו-Git

יש לשמור את ה-Prompt המלא בקובץ:

`prompts/exercise-2.md`

הקובץ חייב להכיל את כל שש השכבות, עם כותרות ברורות.

אין לבצע Git Commit באופן אוטומטי.

אני אבצע סקירה של השינויים ואצור את ה-Commit בעצמי לאחר אישור התוצאה.

## 5. Format — פורמט התשובה

יש לבצע את הפיתוח ישירות בקוד הפרויקט.

בסיום העבודה יש להחזיר תשובה קצרה בעברית, עד 15 מילים, הכוללת:

- האם הפיצ'ר מומש בהצלחה.
- האם כל הבדיקות עברו.
- האם קיימות תקלות או מגבלות שלא נפתרו.

אין לדווח על הצלחה בבדיקות שלא הורצו או שלא עברו.

## 6. Examples — דוגמאות להתנהגות מצופה

**דוגמה 1 — בחירת קובץ PDF**

המשתמש בוחר בקובץ `Documents/Report.pdf`.

המערכת מציגה את פרטי הקובץ הזמינים, את הנתיב היחסי, את גודלו ואת התוכנה הנפוצה לפתיחתו.

לא יוצגו נתוני תמונה או תצוגה מקדימה.

**דוגמה 2 — בחירת תמונה עם EXIF**

המשתמש בוחר בקובץ `Photos/Vacation.jpg`.

פרטי הקובץ הבסיסיים מוצגים מיד כשהם זמינים.

לאחר מכן מוצגים מידות התמונה, נתוני ה-EXIF והתצוגה המקדימה, בהתאם להשלמת הטעינה של כל אחד מהם.

**דוגמה 3 — תמונה ללא EXIF**

המשתמש בוחר בקובץ `Photos/Logo.png`.

המערכת מציגה את פרטי הקובץ, מידות התמונה והתצוגה המקדימה.

באזור ה-EXIF מופיעה הודעה שאין נתוני EXIF זמינים.

**דוגמה 4 — בחירה מהירה בין קבצים**

המשתמש בוחר בקובץ `A.jpg` ומיד לאחר מכן בקובץ `B.jpg`.

גם אם טעינת המידע של `A.jpg` מסתיימת מאוחר יותר, המערכת תציג רק מידע השייך ל-`B.jpg`.

**דוגמה 5 — בחירת תיקייה**

לאחר הצגת פרטי קובץ, המשתמש בוחר תיקייה.

כל המידע על הקובץ הקודם, כולל התצוגה המקדימה ונתוני EXIF, יוסר מהחלונית.
